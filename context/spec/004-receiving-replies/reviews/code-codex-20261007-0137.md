### F1: Recovery can exceed the required 10 seconds
- severity: major
- where: src/chat/receive-loop.ts:RECEIVE_BUDGET_MS and onWake
- problem: Recovery depends on a browser `online` event interrupting a stalled request. If connectivity returns without that event, receiving can remain blocked by the 30-second request budget, then back off another 5 seconds.
- evidence: Functional §2.4 requires replies within 10 seconds after reconnection. The stalled-request test explicitly dispatches `online`; it does not cover recovery while the browser remains marked online, such as an upstream connection interruption.
- fix: Shorten the long-poll timeout and request budget so the remaining request budget plus backoff fits within 10 seconds. Add a stalled-request recovery test that does not dispatch `online`.

## Verdict
SHIP WITH FIXES

The receive loop needs to meet the reconnection deadline without relying on a browser connectivity event.
