### F1: Sending can break chronological ordering
- severity: major
- where: src/chat/chats-store.ts:send / insertByTime
- problem: Incoming messages are inserted by time, but outgoing messages are still appended. If the local clock trails an incoming timestamp, sending breaks ordering and makes the preview and sidebar activity move backward.
- evidence: `messages: [...chat.messages, message]` can produce `[10:01 incoming, 10:00 outgoing]`; `lastActivity()` then reports 10:00. Subsequent incoming insertion assumes this array is sorted.
- fix: Use `insertByTime()` for outgoing messages too; test sending after an incoming message whose timestamp exceeds the local clock.

### F2: Timestamp conversion can poison persisted chats
- severity: major
- where: src/chat/notification.ts:toIncoming
- problem: A finite timestamp can overflow when multiplied by 1,000. The resulting message is acknowledged but corrupts persistence, causing all saved chats to disappear on reload.
- evidence: `timestamp: 1e308` passes `Number.isFinite(timestamp)`, but produces `time: Infinity`. JSON serializes that as `null`; `restoreChats()` rejects the entire chats collection when a message has a nonnumeric time.
- fix: Validate the converted milliseconds against the supported Date range before accepting the message; add an overflow regression test.

### F3: Unsupported replies use the ordinary incoming background
- severity: minor
- where: src/chat/Conversation.tsx:placeholder rendering / Conversation.module.css
- problem: Functional §2.3 requires a grey placeholder bubble, but unsupported replies receive the same white background as text replies in light mode.
- evidence: `.unsupported` only changes text colour and font style; the containing bubble always uses `.in`.
- fix: Apply a placeholder class to the bubble with a grey background.

## Verdict
SHIP WITH FIXES

Fix chronological insertion and timestamp validation before shipping, and give unsupported replies the specified grey background.
