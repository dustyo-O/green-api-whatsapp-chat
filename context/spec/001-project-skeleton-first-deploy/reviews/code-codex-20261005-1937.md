### F1: An older rerun can cancel the latest deployment
- severity: major
- where: .github/workflows/ci.yml:concurrency
- problem: The concurrency group can discard the newest main run, violating §2.2’s automatic publication requirement. The tip guard prevents stale publication but cannot restore the cancelled run.
- evidence: With A running and latest commit B pending, rerunning an older commit replaces pending B. A and the older rerun then skip publication because B is the tip; B never deploys. GitHub documents this [pending-run replacement behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).
- fix: Configure main runs to queue without replacing pending runs, retain the tip guard, and cover this three-run scenario instead of only asserting the YAML structure.
