### F1: Storage write failures leave sign-in permanently busy
- severity: major
- where: src/auth/session-store.ts:signIn and resume
- problem: A localStorage write exception stops execution before the instance check, leaving the form disabled or the reload screen stuck indefinitely. Excluding a save-failure message from scope does not prevent this failure.
- evidence: Zustand persist writes synchronously on every `set`, including `set({ busy: true, error: null })`. Reproducing a throwing storage write left `busy: true` with zero API calls; existing tests never simulate write failures.
- fix: Catch persistence write failures in a storage adapter so in-memory session transitions continue, and add sign-in/reload tests with throwing `setItem`.

## Verdict
SHIP WITH FIXES

Handle storage exceptions before shipping so sign-in cannot become permanently stuck.
