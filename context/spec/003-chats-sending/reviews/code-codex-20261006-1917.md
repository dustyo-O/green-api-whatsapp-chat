### F1: Storage write failures interrupt sending and logout
- severity: major
- where: src/chat/chats-store.ts: send, wipe, storage.setItem
- problem: An uncaught localStorage write failure can clear the draft and leave a message permanently “sending” before any request is made. It can also prevent logout from clearing saved credentials.
- evidence: `send()` calls `patchChat()` before `sendText()`. `wipe()` calls persisted `set()` before `clearStorage()`, and session `signOut()` calls `wipe()` before clearing credentials; a quota/storage exception interrupts each sequence. Tests never simulate storage failures.
- fix: Handle persistence failures explicitly, show a storage error, and ensure logout still attempts chat removal and credential clearing. Add tests with `setItem` throwing.

### F2: Retrying a message does not scroll to the newest message
- severity: minor
- where: src/chat/Conversation.tsx: scrolling effect
- problem: Resending through «Повторить» does not trigger the required scroll when the user has scrolled away from the newest message.
- evidence: The effect depends only on `[chatId, messages.length]`; retry changes status on the same bubble without changing either dependency. The scrolling test covers only a newly appended message.
- fix: Trigger scrolling when a retry starts as well as when a message is appended, and add a retry scrolling test.

## Verdict

SHIP WITH FIXES

Handle storage exceptions before shipping because they can interrupt sending and prevent logout from completing.
