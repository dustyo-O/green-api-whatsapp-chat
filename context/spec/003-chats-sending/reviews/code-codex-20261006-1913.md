### F1: Storage failures interrupt sending and logout
- severity: major
- where: src/chat/chats-store.ts: storage adapter, send, wipe
- problem: A localStorage write failure leaves a message marked sending without issuing the request, and can prevent logout from clearing credentials and saved chats.
- evidence: `localStorage.setItem` is unguarded. `send` persists before calling `sendText`; `wipe` persists before `clearStorage`, and session logout waits for `wipe` to return. No tests simulate storage exceptions.
- fix: Handle persistence failures explicitly, preserve the draft when sending cannot start, show a storage error, and ensure logout still clears storage and credentials. Add quota-failure tests for send and logout.

### F2: A dismissed number check can override a newer chat form
- severity: minor
- where: src/chat/NewChatForm.tsx: start; src/chat/MainScreen.tsx: new-chat toggle
- problem: Closing and reopening the new-chat row leaves the previous check active. Its response can select the old number and close the new form, discarding the number currently being entered.
- evidence: The «+» button remains enabled during checking and unmounts the form. The response guard checks only the session counter, which does not change when the form unmounts.
- fix: Invalidate pending checks on form unmount and ignore their results; add a delayed-response test that closes and reopens the form.

SHIP WITH FIXES

Handle storage failures and stale form responses before shipping.
